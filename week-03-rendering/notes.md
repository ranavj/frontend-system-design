# Week 3 Notes — Rendering

> Format: har build ke baad 3 line — **kya seekha / kis React kaam se juda / kyun ya bottleneck insight**.

## Build 1 — Same App, 3 Ways (CSR vs SSR vs SSG)
- **Kya seekha:** Farak sirf "quote KAB decide hoti hai" ka hai — CSR mein browser mein page-load ke BAAD (View Source khaali milta hai), SSR mein server pe HAR request ke liye (View Source bhara milta hai, refresh pe naya), SSG mein build-time pe EK HI BAAR (`ssg-output.html` kabhi nahi badalta jab tak dobara build na karo). Is build se hum poori tarah **TypeScript** pe shift hue — browser code (`csr.ts`) `tsc` se compile hoke `.js` banta hai, Node code (`ssr-server.ts`/`ssg-build.ts`) `tsx` se direct chalta hai.
- **React/Angular se juda:** Next.js `getServerSideProps` (SSR) / `getStaticProps` (SSG) / plain `useEffect`+`useState` (CSR) — same teen strategies, bas naam diya hua hai. App Router mein `"use client"` bhi yehi "do alag duniya" (browser vs server) ka concept automate karta hai. Angular Universal mein `TransferState` aur `isPlatformBrowser`/`isPlatformServer` bhi same role play karte hain — Angular CLI khud `tsconfig.app.json` (DOM) vs `tsconfig.server.json` (Node) split karta hai, bilkul hamare do tsconfig jaisa.
- **Insight:** `type="module"` script `file://` se CORS error deta hai (module load ek fetch hai, "null" origin allowed nahi) — isliye CSR bhi ab HTTP server se serve karna padta hai. Ek deeper gotcha: agar tsconfig mein `"types"` field bilkul na ho, TypeScript `node_modules/@types/` mein jo mile sab auto-include kar leta hai — humare `tsconfig.browser.json` mein bhi chupke se `@types/node` leak ho raha tha (test kiya: `setTimeout` ka return-type Node vs DOM mein alag hai — `Timeout` vs `number`, explicit type lagate hi conflict pakda gaya). Fix: `"types": []` daal ke browser config ko strictly DOM-only banaya, phir verify kiya ki Node ka `fs` import karne pe turant error aata hai.
